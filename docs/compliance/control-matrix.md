# Control responsibility matrix (NIST SP 800-171)

For each family of NIST SP 800-171 (the controls CMMC Level 2 assesses), what quack
implements, what the operator deploying it must do, and what is inherited from the host or
platform. "quack" means the `quack serve` deployment; the command-line tools run as the
operator on the host and inherit its controls. Links point at the document that describes
the behavior.

| Family | quack implements | The operator must | Inherited from the host |
|---|---|---|---|
| **AC** Access Control | Users, workspace membership with viewer/member/owner roles, API tokens scoped to one workspace with read/write/admin scopes, an admin's self-grant marked `break_glass` with a reason, a disabled user refused everywhere, sessions that expire ([authentication.md](../authentication.md)); an agent that cannot read a workspace it is not run in; writes the agent wants to run are asked for ([design doc 7.4](../design-doc.md)) | Create users and grant roles on a need-to-know basis; disable or remove people who leave; set `[server].trusted_proxies`; put TLS and, where required, a second factor at the identity provider or proxy | Operating-system accounts, file permissions on the data directory, network access to the port |
| **AT** Awareness and Training | — | Train operators on the audit log, the write-permission prompt, and workspace classification labels | — |
| **AU** Audit and Accountability | An append-only access log of every workspace-touching request and every account change, with denied requests, in `control.db`; the content half inside each workspace; OCSF export with model, tools, and cited documents for agent turns ([audit.md](../audit.md)); request ids on every row | Ship the log to a SIEM on a schedule (`quack audit --format ocsf` or the API), retain it per policy, and review `denied` and `break_glass` rows; protect `control.db` from writers other than quack | Log storage integrity, time synchronization (quack stamps rows with the host's clock) |
| **CM** Configuration Management | One `config.toml` with every key listed by `quack config` and unknown keys refused; `quack doctor` checks the setup; dependencies pinned, scanned weekly, and attested at build ([ci-cd.md](../ci-cd.md)) | Keep `config.toml` under change control; upgrade on a schedule using [upgrading.md](../upgrading.md); run `quack doctor` after changes | Package and image provenance verification (`cosign`, SBOM), host hardening |
| **IA** Identification and Authentication | Password login with argon2id hashes and a timed lockout after repeated failures; OpenID Connect sign-in with PKCE and the issuer's access tokens as bearers; API tokens stored as hashes and shown once; the vault seals every stored token under a key in the OS keychain ([authentication.md](../authentication.md)) | Prefer the identity provider for people; rotate API tokens with `--expires`; keep the vault key backed up (`quack vault export-key`) | The identity provider's factors and password policy, the keychain |
| **IR** Incident Response | `quack user disable` ends a person's sessions and refuses their credentials at once; `quack workspace delete` and `delete_document` remove content ([operations.md](../operations.md)); the audit log answers who read what | Write the response procedure around those verbs; report vulnerabilities through [SECURITY.md](../../SECURITY.md) | Host incident tooling |
| **MA** Maintenance | `quack doctor`, `quack embeddings refresh`, workspace snapshots and restores ([operations.md](../operations.md)) | Schedule upgrades and backups; test restores | Host patching |
| **MP** Media Protection | Each workspace is one directory; a snapshot is one tar; `delete_document` removes a document's chunks, vectors, terms, and provenance ([operations.md](../operations.md)) | Encrypt the data volume at rest; sanitize media per the erase procedure; label backups with the workspace's classification | Disk encryption, media handling |
| **PS** Personnel Security | Accounts and memberships can be removed; a removed user's name becomes `removed` in every workspace file | Remove access on departure; review memberships on role changes | HR processes |
| **PE** Physical Protection | — | — | Facility controls of the host |
| **RA** Risk Assessment | Weekly advisory scans, dependency review, nightly parser fuzzing ([ci-cd.md](../ci-cd.md)); the design document names the residual risks (section 15) | Assess the model provider: a workspace's `allowed_providers` is the control that keeps its content from a provider that is not approved for its classification | Platform vulnerability scanning |
| **CA** Security Assessment | Tests, clippy, and the crypto gates on every change; signed and attested releases (SLSA Build Level 3) | Assess the deployment against this matrix; keep evidence (`quack doctor --format json`, the audit export) | Platform assessments |
| **SC** System and Communications Protection | TLS 1.2/1.3 with a post-quantum hybrid key exchange on every outbound connection, aws-lc-rs as the only crypto provider and the FIPS module on Linux ([crypto.md](../crypto.md)); workspaces isolated in separate DuckDB files with a confined connection; `allowed_providers` per workspace; proxies honored; no inbound TLS of its own | Terminate TLS in front of `quack serve`; bind to loopback or a private network; restrict egress to the approved providers | Network segmentation, the proxy's TLS |
| **SI** System and Information Integrity | Strict parsing with decompression limits, prompt-injection fences around retrieved text, writes the agent wants to run held for a person after it has read documents, panics denied by lint ([design doc 7.4](../design-doc.md)) | Watch the advisory issues the weekly scan opens; upgrade on fixes | Host malware protection, OS updates |
