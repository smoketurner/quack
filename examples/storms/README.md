# Storms: NOAA's Storm Events Database, 2024

One public-domain dataset that exercises everything quack does: three linked tables with
real keys, narratives, dollar amounts, and dates for SQL and charts; the government
documents that define every code in those tables, for search and cited answers; an
HTTP import of Census population figures to join against; a hand-written ontology
mapped onto the tables so the knowledge graph is built without a model; and enough
prose (10,000 episode narratives, a 70-page NWS instruction) for the model-driven
extraction steps when a model is available.

```bash
make demo-data                                   # load into the workspace named "storms"
examples/storms/load.sh WORKSPACE                # load into WORKSPACE (created if missing)
examples/storms/load.sh WORKSPACE --reset        # delete every document in WORKSPACE first, then load
```

Loading takes a minute or two after the downloads (about 85 MB of CSV, cached under
`~/.cache/quack/examples/storms/`). It is idempotent: files already in the workspace are
skipped, derived tables are built only when missing, and the ontology and graph are
written only once. Nothing in `load.sh` calls a model.

## What is loaded

| Item | What it is | Source |
|---|---|---|
| `events` table | 69,801 storm events: type, county or zone, forecast office, begin and end time, direct and indirect deaths and injuries, property and crop damage, wind or hail magnitude, tornado rating and path, coordinates, and the episode and event narratives. Loading adds `begin_time_ts`, `end_time_ts`, `damage_property_usd`, and `damage_crops_usd`, parsed from the text columns | [NCEI Storm Events Database](https://www.ncei.noaa.gov/stormevents/), bulk CSV files. US government work, public domain. |
| `fatalities` table | 1,141 people killed, one row each: direct or indirect, age, sex, where they were, linked by `event_id` | same |
| `locations` table | 41,574 points along event paths, linked by `event_id` | same |
| `state_population` table | The Census Bureau's 2024 state population estimates, pulled straight over HTTPS with `quack import` | [Census Bureau](https://www.census.gov/data/tables/time-series/demo/popest/2020s-state-total.html). Public domain. |
| `states` table | One row per state with the name in capitals to match `events.state`, FIPS code, Census region, and 2024 population, built from `state_population` with a `CREATE TABLE ... AS SELECT` through `quack -q` | derived |
| `notable_events` table | The 1,528 events with any casualty, an EF2 or stronger tornado, or property damage of a million dollars or more; the table the graph is built from | derived |
| `storm-events-glossary.md` | How to read every code in the tables (event types, `D`/`I`, `EG`/`MG`, `10.00K`), pinned so it is in every prompt | [documents/](documents/) in this directory |
| `Storm-Data-Bulk-csv-Format.pdf` | NOAA's column-by-column reference for the CSV files | [NCEI](https://www.ncei.noaa.gov/pub/data/swdi/stormevents/csvfiles/Storm-Data-Bulk-csv-Format.pdf) |
| `nws-instruction-10-1605.pdf` | NWS Instruction 10-1605, Storm Data Preparation: what may be entered, how each event type is defined, how deaths and damage are attributed | [National Weather Service](https://www.weather.gov/directives/) |
| `enhanced-fujita-scale.html` | The Storm Prediction Center's explanation of the EF Scale and its damage indicators | [SPC](https://www.spc.noaa.gov/efscale/) |
| `saffir-simpson-scale.html` | The National Hurricane Center's page on the Saffir-Simpson Hurricane Wind Scale | [NHC](https://www.nhc.noaa.gov/aboutsshws.php) |
| Workspace context | What the tables hold, which columns to use for dates, money, and magnitude, and when to cite which document | [context.md](context.md) |
| Ontology | Five classes (episode, storm event, fatality, state, forecast office), four relations, twenty typed properties, and mappings onto `notable_events`, `fatalities`, and `states` | [ontology.json](ontology.json) |
| Knowledge graph | 3,667 nodes and 5,725 edges built from the mapped tables, with a row-level source on every edge | `quack graph extract --tables-only` |

The Storm Events files are regenerated by NOAA every few months under a new name
(`StormEvents_details-ftp_v1.0_d2024_c20260728.csv.gz`); `load.sh` reads the directory
listing and takes the newest 2024 file for each table, so counts can drift a little
from the ones above.

## Try it

Ask across the tables, with charts:

```bash
quack -w storms -p "which states had the most direct deaths in 2024, and from what kind of weather?"
quack -w storms -p "chart property damage by month"
quack -w storms -p "deaths per million residents by state, top ten"           # joins events to states
quack -w storms -p "how long was the longest EF4 tornado track, and where?"
quack -w storms -p "what did Helene do in North Carolina?"                    # episode narratives
```

Ask the documents, cited, in query mode:

```bash
quack -w storms -p "what is the difference between a direct and an indirect fatality?" --mode query
quack -w storms -p "what wind speeds define an EF3?" --mode query
quack -w storms -p "when is an event entered as Excessive Heat rather than Heat?" --mode query
```

Walk the graph:

```bash
quack -w storms graph search 'NORTH CAROLINA'        # every notable event in the state, their episodes, offices, and fatalities
quack -w storms graph search 1184254                 # the Osage County EF4: two fatalities, its episode, Oklahoma, WFO TSA
quack -w storms graph path 58277 GSP                 # a fatality -> its flash flood -> the office that recorded it
quack -w storms graph status
quack -w storms -p "which forecast offices recorded events that killed people in mobile homes?"   # the agent uses search_graph
```

SQL without the agent, or with piped data:

```bash
quack -w storms -q "SELECT event_type, count(*) n, sum(deaths_direct) deaths FROM events GROUP BY 1 ORDER BY deaths DESC LIMIT 10" -f markdown
quack -w storms -q "SELECT date_trunc('month', begin_time_ts) AS month, round(sum(damage_property_usd) / 1e6) AS usd_millions FROM events GROUP BY 1 ORDER BY 1" -f csv
cat ~/.cache/quack/examples/storms/fatalities.csv | quack -w storms -q "SELECT fatality_location, count(*) n FROM stdin GROUP BY 1 ORDER BY n DESC"
```

Sessions, sharing, and the other interfaces:

```bash
quack -w storms -p "and how many of those were indirect?" -c        # continue the last session
quack -w storms sessions ; quack -w storms export ID --markdown      # transcripts, or --sql for the statements
quack -w storms okf export ./storms-okf                              # the whole workspace as a Markdown bundle
quack serve --local                                                 # web UI: chat, tables, SQL, documents, the graph page, the ontology
quack mcp -w storms                                                 # MCP over stdio; see .mcp.json below
```

For Claude Code or an editor, one line in `.mcp.json` gives the assistant `query`,
`search`, `sql`, `search_graph`, and `find_path` over this workspace:

```json
{ "mcpServers": { "storms": { "command": "quack", "args": ["mcp", "-w", "storms"] } } }
```

## With a model

The loader stops where model calls begin. With a chat model configured, three more
steps finish the picture:

```bash
quack -w storms ontology propose --documents --sample 40    # what the documents mention that the ontology lacks; review and accept
quack -w storms graph extract --documents-only --sample 100          # named entities and relations from the narratives and the NWS instruction, with chunk provenance
quack -w storms graph merges                                         # near-duplicate labels the extractor proposed to merge
```

`[retrieval].rerank = "model"` in the config turns on reranking of retrieved chunks for
the query-mode questions above; the NWS instruction is long enough for it to matter.

## Why this dataset

- **Real keys.** `episode_id` and `event_id` tie three files together, and `state`
  joins to the Census table, so ontology induction (`quack ontology propose`) finds the
  relations on its own and the shipped ontology maps them exactly.
- **Codes that need documents.** `D` or `I`, `EG` or `MG`, `EF2`, `10.00K`: none of it
  is self-explanatory, and the government documents that define each are public. The
  pinned glossary answers the common ones; the NWS instruction has the rest.
- **Numbers worth charting.** Casualties, dollars, dates, and coordinates, with a
  September that dwarfs every other month (Helene) and states that lead on deaths per
  capita rather than in total (Arizona and Nevada, from heat).
- **Prose for extraction.** Every episode has a narrative naming places, storms, and
  what happened, and the instruction's appendix is full of worked examples, so
  model-driven extraction has something to find.
- **Something people know.** Helene, the 2024 tornado season, the Las Vegas heat: the
  questions write themselves.

## Adding an example

Make a directory under `examples/` with a `README.md` like this one, a `load.sh` that is
idempotent and takes `[WORKSPACE] [--reset]`, the documents it writes as real files, a
`context.md`, and an `ontology.json` when the tables have keys worth mapping. Only use
data whose license allows redistribution, and say what it is.
